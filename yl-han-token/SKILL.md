# yl-han-token

为用户指定的 Agent 接入自定义模型，并用实际请求核实结果。Codex 的目标是：同一会话保留上下文，常规 → 自定义 → 常规以及自定义之间均能切换，下一轮按所选模型调用。

面向用户的聊天调用、批量输入及命令行案例见 [README.md](README.md)；仅在需要使用说明时读取。

## 独立运行入口

此技能自带运行代码和 tomlkit 依赖，不需要另行克隆项目或访问作者电脑。将技能目录中的 `scripts/hantoken.py` 绝对路径记为 `<入口>`，所有路径相对技能自身解析。

当前支持 Windows，需 Python 3.10+ 和已安装的目标 Agent。优先使用环境中已有 Python（含可用的应用内置运行时），无 Python 时明确说明先决条件，不能声称零运行时可用。Codex/WorkBuddy 无需 pip 安装依赖；Trae 首次使用时入口会在技能目录内建立独立环境并安装 Playwright，不下载浏览器。

首次安装、迁移或怀疑技能损坏时执行 `python -X utf8 "<入口>" self-check`。常规导入直接执行 `apply`，其内部会在写入前检测目标客户端或 CLI，无需另起 `detect` 进程重复检测。仅有配置目录不代表安装成功；未安装时停止，不创建凭据或无效配置。单独排查安装路径时使用 `detect --agent <目标>`。

导入时优先用 `python -X utf8 "<入口>" apply --agent <目标> --stdin`，经标准输入传用户给出的 JSON；不要把密钥嵌入 shell 命令。也可 `gui --agent <目标>` 打开界面由用户粘贴，或 `--input <用户提供的文件>`。目标按下面的规则确定，命令中始终显式传入 `--agent`。

## 常规导入的最短流程

确定宿主或显式目标后，只读本技能及 [references/workflows.md](references/workflows.md) 中对应客户端分支，将整批输入交给一次 `apply`。已有可靠入口时不重新扫描项目、读取源码、运行全量测试或构建分发包。

使用工具支持的标准输入传递 JSON；已有用户文件则用 `--input`。工具无法安全传递输入时，使用 GUI 供用户粘贴，不从历史会话日志或截图提取密钥，不反复试验 PTY 输入方式。已有的 URL 清理和模型解析交给公共解析器。

以本次适配器结果为准验证和汇报：Codex 导入已执行桌面兼容性校验，Trae 已执行原生连通性检查，WorkBuddy 已回读配置（不等同于网络调用成功）。需要实际连接验证时仅验证本次新增/更新的模型；同一次操作已有可靠请求证据时不再重复相同检查。发现原服务商问题时单独报告，不把常规导入扩展为全部模型修复或双向切换回归。用户要求切换验收或修改路由实现时再使用完整切换流程。

耗时排查可给 `apply` 加 `--timings`，标准错误输出仅含阶段名称和秒数，不含输入或密钥。Trae 复用现有 CDP 和批次连接；不要为了常规导入关闭带调试端口的客户端。WorkBuddy 内容未变化时校验后跳过写入和备份。

### Trae CN 自身窗口的执行限制

默认目标仍可由宿主确定。Trae CN 普通启动未开启 CDP 时，自动配置需要完全退出（含托盘）后由外部工具以调试模式启动；手动添加可在当前窗口直接完成。在 Trae 自己的聊天窗口调用本技能时，关闭 Trae 会中断当前 Agent，不能承诺关闭后原窗口能继续完成配置。

若当前宿主是 Trae 且没有可用 CDP，优先给出留在当前窗口的手动引导，不只提示关闭或换客户端：点击输入框附近的模型下拉菜单 → 添加模型 → 模型设置页的「+ 添加模型」→ 自定义模型。逐项说明 API 格式、请求地址、模型 ID、显示名和 API 密钥的填写方式，见 [README 手动引导](README.md#在-trae-当前窗口内手动添加无需关闭)。按本次输入提供可复制的地址和 ID；密钥提示使用用户刚提供的原值，不在回复中明文复述。未实际操作或用户未确认时，只能说明已提供引导，不能声称配置或连通性检查成功。

用户选择自动配置时，再说明外部路径：在 Codex、WorkBuddy 中明确要求“配置 Trae CN”，或从 Trae 之外打开本工具 GUI / 独立 PowerShell；保存工作并完全退出 Trae，再从该外部入口执行配置。不要把 Trae 集成终端当成独立外部终端，不自动关闭客户端，不使用强杀进程或延时脚本绕过当前窗口退出问题。已有可用 CDP 时直接复用，无需关闭。

已在独立「自定义模型一键配置」窗口操作时，不再把缺少 CDP 当成即时失败：粘贴后点击一次「校验并写入」，窗口会保留本批配置并提示等待退出。用户保存工作、完全退出 Trae（含托盘）后，工具自动以调试模式启动并继续导入，无需重新粘贴或点击。关闭的是 Trae，不是本工具窗口；最多等待 3 分钟，超时后输入仍保留可重试。此窗口流程与 Trae 自己的聊天窗口不同。

## 默认配置调用技能的 Agent

- 用户本次明确指定目标时，以指定目标为准。例如在 WorkBuddy 中要求“配置 Trae CN”，只配置 Trae CN。
- 用户只提供模型 JSON、说“配置模型”或“添加自定义模型”，未额外指定目标时，默认配置当前调用技能的宿主 Agent：在 WorkBuddy 中调用就配置 WorkBuddy，在 Trae CN 中调用就配置 Trae，在 Codex 中调用就配置 Codex。宿主明确时直接执行，不再询问目标。
- 从可信的调用环境确定宿主，不把其他客户端正在运行、项目目录名称或入口脚本默认参数当成宿主证据。宿主无法确定时，可使用本次任务中已明确的唯一目标；仍有歧义才询问。
- `--agent` 的值为 `Codex`、`WorkBuddy` 或 `Trae`（对应 Trae CN）。一次只配置选定 Agent 的自定义模型，保留其自带模型及其他客户端配置；用户明确要求多个目标时才批量处理。

Codex 导入默认将本次第一项设为默认模型，与项目界面默认勾选「同时将第一项设为默认模型」一致，成功后明确报告默认选择。用户明确要求「保留当前默认」「只添加不切换」时传 `--keep-default`；仅说「保留其他已有模型」仍保留模型列表并默认选择第一项。输入中明确的 `codex.setDefault` 优先于自动选第一项；`--keep-default` 优先保留当前选择。此规则仅适用于 Codex，WorkBuddy / Trae 不据此改动当前聊天选择。兼容性失败时仍不提交默认模型变更。

诊断用 `diagnose`，同会话核验用 `switch-check --models <常规ID> <自定义A> <自定义B> <常规ID> --report <脱敏报告路径>`。详细参数和运行代码位置见 [references/workflows.md](references/workflows.md)。

## 按任务处理

- **导入配置**：读 [references/workflows.md](references/workflows.md) 的输入及 Agent 分支。支持 `{id,url,apiKey}` 或这类对象的数组；多个模型不能因为共用 URL/密钥而只保留一个。
- **Codex 模型菜单或同会话切换**：使用统一模型目录及按模型 ID 路由的入口。单纯保存 CLI profile，不能满足桌面菜单切换要求。启用或恢复需按用户本次目标处理，不从历史记录推定当前状态。
- **无法调用、重复模型、切换后仍回答旧型号**：读 [references/diagnostics.md](references/diagnostics.md)，先关联本次会话和本次调用，不直接改提示词或重新导入全部配置。
- **恢复或退出登录**：区分恢复原服务商配置与清除登录凭据。采用项目已有事务和备份流程，保留无关 MCP、插件、会话及用户改动。

## 配置与调用的不变量

1. 密钥只从用户输入、既有安全存储或用户环境变量读取。技能、报告、日志、示例、命令行不写真实密钥。不复用先前会话中暴露的密钥作为内置默认值。
2. 遵守当前文件系统与网络权限；安装技能的授权不等于授权任意切换服务商。用户已经要求实施的配置可直接推进，不额外设置确认流程。
3. 写入前保留备份，通过适配器事务提交。处理并发改动和失败回滚；保留原 `model_provider` ID、认证方式和 `auth.json`，以支持旧会话继续使用。
4. 模型显示名称按客户端处理：WorkBuddy、Trae 已有原生“自定义模型”分组或标签，保留用户提供的 `name`，未提供时使用模型 ID，不添加 `自定义模型 / ` 前缀。仅 Codex 模型列表没有原生分组标题时，自定义项使用该前缀并如实说明；常规模型保留原显示名。
5. 去重只处理自定义模型，不修改客户端自带模型及其名称、目录、配置。WorkBuddy 的本地 `models.json` 自定义列表按去掉首尾空格、区分大小写的 `id` 去重；已有列表和本次批量输入均保留同 ID 的最后一条，导入时按 ID 更新，名称、地址或密钥变化不再新增副本。不同 ID 分别保留。Trae 使用原生自定义模型存在检查。Codex 自定义路由仍按实际端点、协议、模型和账号去重，不同账号不能误合并，旧重复 ID 可作为隐藏兼容别名；不得擅自把一个实际模型映射成另一个。
6. 请求中的模型 ID 必须与选择一致，并核对上游报告的 ID。型号不同或缺失时明确失败，不能替换 ID、重写回答或静默回退来伪装成功。型号不匹配使用不可重试的验证错误，避免重连循环。
7. 模型自称不是路由证据。不要添加让模型自称某型号的补偿提示，不要把 API 返回字段说成对第三方内部权重的独立鉴定。
8. 不强制退出正在使用的 Codex，不修改外部安装 BAT。配置加载需要重开时说明仅需一次；逐轮切换不应要求新建聊天或重启。

## 验收与交付

按用户范围验证。涉及 Codex 同会话切换时，使用临时 `CODEX_HOME` 的原生 app-server 实际完成常规 → 自定义 A → 自定义 B → 常规；检查每轮工具调用、最终回答、所选/发送/返回模型 ID。需要支持旧会话时额外验证原服务商会话恢复。测试操作不得使用真实用户聊天作为可写试验场。

明确区分源代码修复、已安装运行服务、磁盘配置、运行中桌面和测试结论。测试目录成功不代表主配置已启用；磁盘配置改变不代表桌面已重新加载。仅测试一个常规模型时，不声称全部常规模型均可用。

报告已实施内容、已验证的切换方向、未解决原因和下一步。若只有自定义之间通过而常规失败，整个双向切换目标仍未完成，继续定位明确故障或说明外部阻碍。给出可复查的脱敏报告路径。
