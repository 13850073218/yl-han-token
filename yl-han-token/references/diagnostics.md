# 实际调用与故障定位

## 先建立本次证据

读取当前配置和安装服务 settings 中的端口、instance、脚本 hash；从该端口 `/health` 检查实例，不沿用历史固定端口。仅输出字段，不打印整个配置或认证文件。

对照本次会话的时间和 `turn_context.model`，以及最近路由的 `requested_model`、`upstream_model`、`response_model`、`upstream_host`、`wire_api`、`status`、`http_status`。会话的模型选择与网关记录需同时核对；选择器显示或回答自称都不足以证明调用路径。

历史会话通常位于实际 `CODEX_HOME/sessions` 的 JSONL；必要时只读相应会话。默认只输出型号、时间和结构性诊断，不把用户会话正文、工具参数或凭据复制到公开报告。

`/health` 的路由历史为内存中最近 24 条，重启清空；做运行服务修复前保存必要的脱敏证据。`at` 是请求开始时间，完成顺序可能不同。主配置恢复直连后，网关旧记录不能代表当前请求；运行中的桌面也可能仍使用旧配置。

## 按证据分支

| 证据 | 处理 |
| --- | --- |
| 选择自定义但请求 ID 仍是常规 | 定位当前会话选择、运行进程配置、profile 和目录缓存；检查是否只改显示名，没有接入路由 |
| 请求和发送为自定义、返回 ID 匹配，但自称 GPT | 实际路由通过；查既有上下文、指令和第三方回答。可以隔离复现，但不能通过改写回答或身份暗示伪造修复 |
| 所选与返回 ID 不同 | 上游别名、映射或不支持。明确列出差异；拒绝响应，不静默更换模型。客户端应收到不可重试错误 |
| HTTP 401 | 上游拒绝认证。确认具体服务商、凭据来源和账号状态；不要拿自定义密钥替换常规密钥 |
| HTTP 403 | 可能是访问规则、权限或请求客户端差异。与原生 Codex 同参数请求对比，不能仅凭普通 urllib/curl 失败判定 Codex 不可用 |
| `reasoning.effort` 不支持 | 使用该模型能力目录支持的值；不要全局强制 `none` 或 `high` |
| `unknown variant namespace` | 协议不兼容；若实际 Chat 接口可用，使用 Chat 桥接与命名空间转换，不据此判定服务商整体不可用 |
| `web_search` 转换失败 | Chat 路由可省略可选内置搜索，强制搜索明确失败；保留常规 Responses 搜索行为 |
| 429/503、queue full | 容量或限流，遵循现有有限重试；工具与最终回答没完成就不报告通过 |
| provider mismatch / 旧聊天无法继续 | 检查根 provider ID 是否被替换、原 ID 的配置是否仍存在；通过保留原 ID 的路由入口验证恢复 |
| WorkBuddy 重复自定义选项 | 仅对本地 `models.json` 自定义列表按 ID 去重，同 ID 保留最后一条；名称、地址、密钥不同不再新增。保留客户端自带模型 |
| Codex 重复自定义选项 | 按端点+协议+型号+实际账号去重，检查旧 provider/env 名变更；不同型号/账号不可误合并，保留自带模型 |
| Trae 已存在卡住 | 给提示短暂缓冲后关弹窗并返回跳过结果，继续下一个；不等整段超时 |

## 核验边界

常规与自定义调用可走不同协议、地址、认证及能力集合，不能共享一套参数强行验收。单次直连成功不代表统一入口正常，预览服务成功不代表安装服务正常。先复现一个明确故障，再修复对应层，完成实际同会话验证后才宣布相关方向可用。

API model 字段仅代表上游声明。没有独立证据时，不声称已经识别第三方内部模型权重；也不声称某个模型“说不知道型号”意味着根本没有切换。
